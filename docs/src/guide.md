# Guide

This guide walks through constructing, using, and closing a `PoolQueue`, and
covers exception-safety considerations.

## Constructors

There are several constructor forms.  All of them pre-populate the pool unless
you construct from raw channels.

### From a type constructor

```jldoctest
julia> using PoolQueues

julia> pq = PoolQueue(Int, 3, 3, 0);    # 3 Ints (initialized to 0), 3-slot queue

julia> nitems(pq)
(3, 0)
```

Pass `Tq` explicitly to give the queue a different element type than the pool:

```jldoctest
julia> using PoolQueues

julia> pq = PoolQueue(Int, String, 3, 2, 0);   # pool: 3 Ints, queue: 2 Strings

julia> maxsize(pq)
(3, 2)
```

### From a factory function

```jldoctest
julia> using PoolQueues

julia> pq = PoolQueue(() -> zeros(Float64, 4), 2);  # 2 vectors of Float64

julia> acquire!(pq)
4-element Vector{Float64}:
 0.0
 0.0
 0.0
 0.0
```

Use the parameterized form when the factory may return varying concrete types:

```jldoctest
julia> using PoolQueues

julia> pq = PoolQueue{Number, Number}(2, 2);

julia> recycle!(pq, 1); recycle!(pq, 2.0);

julia> nitems(pq)
(2, 0)
```

### From raw channels

For full control (including `RemoteChannel`s for distributed use), construct
from two channels directly:

```jldoctest
julia> using PoolQueues

julia> pq = PoolQueue(Channel{Int}(2), Channel{Int}(2));

julia> maxsize(pq)
(2, 2)
```

## Producer and consumer tasks

The function forms of `produce!` and `consume!` are preferred because they
guarantee that items are acquired and recycled correctly, including on
exceptions.

```julia
producer = @async for i in 1:5
    produce!(pq) do item
        item[] = i     # mutate in place
        return item
    end
end

consumer = @async for _ in 1:5
    consume!(pq) do item
        println("got ", item[])
        return item
    end
end
wait(consumer)
```

Returning `nothing` from the producer's function recycles the item without
producing it - handy for filtering or signalling end-of-input.

## Exception safety

Both function forms are exception-safe:

- If the function passed to `produce!(f, pq)` throws, the acquired item is
  recycled back to the pool and the exception is rethrown.
- If the function passed to `consume!(f, pq)` throws, the consumed item is
  recycled back to the pool when `queueitem isa Tp`; otherwise it cannot be
  recycled and is dropped (with a warning) before the exception is rethrown.

This means a producer or consumer that throws will not silently leak items out
of the pool, provided the consumed value is pool-compatible.

## Closing

`close(pq)` closes the queue and pool channels in that order.  The `PoolQueue`
is unusable after `close`; further `acquire!`/`produce!`/`consume!`/`recycle!`
operations will throw.

```jldoctest
julia> using PoolQueues

julia> pq = PoolQueue(Int, 2, 2, 0);

julia> # Drain the pool so acquire! must block, then close to wake it.

julia> acquire!(pq); acquire!(pq);

julia> close(pq);

julia> try acquire!(pq) catch e typeof(e) end
InvalidStateException
```

## Introspection

Use `nitems` and `maxsize` to inspect a `PoolQueue` (or any underlying
`Channel`/`RemoteChannel`):

```jldoctest
julia> using PoolQueues

julia> pq = PoolQueue{Int,Int}(2, 3);   # empty pool/queue, no pre-population

julia> maxsize(pq)
(2, 3)

julia> recycle!(pq, 1); recycle!(pq, 2);

julia> nitems(pq)
(2, 0)

julia> item = acquire!(pq);

julia> produce!(pq, item * 10);

julia> nitems(pq)
(1, 1)
```
